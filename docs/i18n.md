# Translations (`native-signal-ui/i18n`)

Reactive UI text. Each key of a translation file is a `Computed<string>` that
follows a locale the app supplies, so `<h1>{tr.title}</h1>` rewrites itself when
the language changes. It is its own import path and touches no DOM; apps that
don't translate don't carry it.

## Set up once per app

The app decides which languages exist and where the active locale comes from:

```ts
// src/translation.ts
import { create_translations, type TranslationMap as Map } from "native-signal-ui/i18n";
import { locale } from "./state";

export const LANGUAGES = ["de-DE", "en-US"] as const;
export type Language = typeof LANGUAGES[number];
export type TranslationMap = Map<Language>;

export const TranslationProvider = create_translations({ languages: LANGUAGES, locale });
```

- **`languages`**: every supported tag. Each entry must carry a text for all of
  them, checked at compile time. Pass it `as const` (or inline) so the tags stay
  literal types.
- **`locale`**: anything with a tracked `get(): string`, a `NativeSignal` or a
  `Computed`. An app usually passes a Computed over its user and settings. A
  tool that has to set the language itself (a designer, a test) passes a
  writable `NativeSignal`, or a Computed over one. There is no separate
  override.
- **`fallback`** (optional): read when the locale is not one of `languages`.
  Defaults to `languages[0]`.

Two systems in one page are independent: each `create_translations` call has
its own locale.

## Translation files

```ts
// Dialog.translation.ts
import { TranslationProvider } from "/src/translation";
import common from "./common.translation";

export default TranslationProvider.create({
    title:  { "de-DE": "Titel", "en-US": "Title" },
    cancel: { "de-DE": "Abbrechen", "en-US": "Cancel" },
}, common);
```

```tsx
import tr from "./Dialog.translation";

<button>{tr.cancel}</button>            // reactive text
<input placeholder={tr.title} />        // reactive attribute
tr.title.get();                         // the current string, once
```

- Arguments after the map are **extended** providers (made by `create`; a
  raw map is a type error and throws, spread it into the map instead): keys the map does not
  define resolve through them, recursively. An own key wins over an extended
  one. An extended key returns the extended provider's own `Computed`, so
  `page.cancel === common.cancel`.
- Each key's `Computed` is built on first access and then cached.
- A provider exposes **only its keys**. A key may be called `get`, `has` or
  `constructor`; there are no methods to collide with. An unknown key reads as
  `undefined` (and is a type error).

## Computed texts

A text does not have to be written out. Where it depends on state other than
the language, give that language a `Computed<string>` (or any `NativeSignal<string>`)
instead of a string:

```ts
const formal = new NativeSignal(false);  // e.g. an app setting

export default TranslationProvider.create({
    hello: { "de-DE": new Computed(() => formal.get() ? "Guten Tag" : "Hallo"), "en-US": "Hello" },
});
```

`tr.hello` is still one `Computed<string>`. It reads the active language's text
inside itself, so it follows both the locale and whatever the computed text
reads. Nothing that shows `tr.hello` has to know the text is computed. An app
that does this for many entries usually wraps it in a helper
(`gender("Klient", "Klient:in")`).

## Types

| Export | Purpose |
| --- | --- |
| `create_translations(options)` | Set up a system; returns `{ languages, locale, create }` |
| `Translation<L>` | One entry: `Record<L, TranslationText>` |
| `TranslationText` | One language's text: `string` or a `TextSource` |
| `TextSource` | `{ get(): string }`, a computed text's shape |
| `TranslationMap<L>` | A file's keys to entries |
| `TranslationProxy<T, E>` | What `create` returns |
| `Translations<L>` | What `create_translations` returns |
| `LocaleSource` | `{ get(): string }`, the locale's shape |
| `AnyTranslationProxy` | What `extend` accepts: any provider made by `create` |

An own key's type is the union of its literal texts (`Computed<"Titel" | "Title">`,
a computed text contributing `string`),
so ctrl-click on `tr.title` jumps to the entry. Extended keys are
`Computed<string>` and have no go-to-definition. `keyof typeof tr` is exactly
the keys, own and inherited, at any depth of `extend`, so `tr[k]` for a
computed `k` is always a `Computed<string>`.

An entry with an extra language beyond `languages` is accepted and ignored; a
misspelt one fails because the correct tag is then missing.
